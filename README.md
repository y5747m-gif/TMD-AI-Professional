# مشكاة — Mishkat

> **أداة ذكاء اصطناعي احترافية للإجابة على الأسئلة الدينية من نصوص قناة علمية على يوتيوب**
> تعرض النص المستخرَج، وتوقيته، ورابط الفيديو المتعلق بسؤال المستخدم — مع قاعدة بيانات محلية ومحرك ذكاء اصطناعي منفصل قابل للتبديل.

القناة المعتمدة: [`UCv0g_v1C6JcZALvrkDu98AQ`](https://youtube.com/channel/UCv0g_v1C6JcZALvrkDu98AQ) — ثابتة داخل الأداة في كل مكان.

---

## ١) ما الذي تفعله الأداة؟

1. **تسرد** كل فيديوهات القناة.
2. **تستخرج النصوص** (الترجمة/التفريغ) لكل فيديو.
3. **تنظّف** النص وتقسّمه إلى مقاطع زمنية (Chunks) تحمل توقيت البداية والنهاية.
4. **تفهرسها** في قاعدة بيانات محلية (SQLite + FTS5 عربي).
5. **تبحث** بحثًا هجينًا (مرادفات شرعية + تطبيع همزات/تشكيل + إعادة ترتيب حسب تغطية كلمات السؤال).
6. **تجيب** بمحرك ذكاء اصطناعي منفصل (Gemini / Groq / OpenAI / OpenRouter / أي مزوّد متوافق)، أو بمحرك استخراجي مبني على النص مباشرة إن لم يوجد مفتاح API.
7. **توثّق الإجابة**: تُرفق كل فقرة بمصدرها `[المصدر 1]` + التوقيت `02:15` + رابط يفتح الفيديو عند اللحظة نفسها.
8. **توسّع المجال**: ثلاثة أوضاع للإجابة — صارم، متوازن، وواسع المجال (استفاضة في المسائل المتصلة والمذاهب والنوازل).

## ٢) التشغيل السريع (ثلاث خطوات)

```bash
# ١) تشغيل الواجهة (لا يحتاج أي تثبيت مكتبات)
npm start                # أو: node mishkat/server.js

# ٢) في نافذة أخرى: سحب نصوص القناة إلى قاعدة البيانات
npm run ingest           # كل الفيديوهات — أو: npm run ingest -- --limit 20

# ٣) تشغيل المحرك الذكي (اختياري — الأداة تعمل بدونه)
cp .env.example .env     # ثم ضع مفتاحًا واحدًا مثل GEMINI_API_KEY
```

ثم افتح: <http://localhost:3000>

> مهم: أمر السحب `npm run ingest` يجب أن يُشغَّل على جهاز متصل بالإنترنت (جهازك أو أي خادم).
> بعض البيئات المغلقة (Sandbox) لا تسمح بالوصول إلى youtube.com، ولذلك تظهر الواجهة ببيانات تجريبية حتى تسحب النصوص الحقيقية.

### ٢-ب) استعادة «بيانات القناة الحقيقية» بأمر واحد

السكربت التالي ينفّذ العملية كاملة من البداية للنهاية: فحص الاتصال → حذف البيانات التجريبية → سحب نصوص القناة الحقيقية → تصدير `mishkat/data/index.json` → الاختبارات → الالتزام برسالة **«مشكاة: بيانات القناة الحقيقية»** → الدفع إلى `main` → **التحقق من نجاح الدفع** بمطابقة المعرّف البعيد مع المحلي:

```bash
npm run restore                # العملية كاملة حتى الدفع والتحقق
npm run restore -- --limit 10  # تجربة سريعة على 10 فيديوهات (بدون دفع يفضَّل أولًا)
npm run restore -- --no-push   # سحب والتزام دون دفع
npm run restore -- --force     # إعادة سحب كل الفيديوهات من جديد
```

> شغّله على جهاز/خادم يصل إلى youtube.com مباشرة. البيئات المعزولة (بعض Sandbox/CI) تحجب يوتيوب وسيفشل الفحص المبكر في الخطوة [1/8] برسالة توضح ذلك.

#### إدخال البيانات عبر طلب سحب (PR) بدل الدفع المباشر

إن أردت مراجعة البيانات قبل دخولها `main` (وهو الأنسب للمستودعات المحمية):

```bash
npm run restore -- --pr             # سحب → تصدير → اختبار → التزام على فرع mishkat/real-data-… → فتح PR
npm run restore -- --pr --merge     # …ثم دمج الـPR في main (squash) والتحقق من وصول البيانات
npm run restore -- --dry-run --pr --merge   # محاكاة: يطبع الأوامر فقط (بلا شبكة ولا التزام ولا دفع)
```

| العلم | الوظيفة |
| --- | --- |
| `--pr` | يدفع فرع بيانات مستقلًا ويفتح طلب سحب إلى `main` عبر `gh` بدل الدفع المباشر |
| `--merge` | يدمج طلب السحب (squash) بعد إنشائه — يتطلب `--pr` |
| `--dry-run` | محاكاة كاملة: يطبع أوامر `git`/`gh` التي ستُنفَّذ دون تنفيذها |
| `--branch=الاسم` | تحديد اسم فرع البيانات (الافتراضي `mishkat/real-data-YYYYMMDD-HHMM`) |
| `--base=الفرع` | الفرع الهدف لطلب السحب (الافتراضي `main`) |

**التحقق بعد الدمج** لا يقارن `sha` الالتزام (لأن الدمج بطريقة squash يُنتج التزامًا جديدًا) بل يقارن **بصمة ملف البيانات** في `origin/main` مع المحلية:

```bash
git fetch origin main
git rev-parse origin/main:mishkat/data/index.json   # يجب أن يطابق:
git rev-parse HEAD:mishkat/data/index.json
```

وضع `--pr` يحتاج GitHub CLI مثبّتًا ومسجَّل الدخول (`gh auth login`).

ملاحظة: الفيديوهات التي لا تحتوي ترجمة/تفريغًا على يوتيوب لا يمكن فهرستها؛ تُسجَّل في القاعدة مع سبب واضح، ويُمكن تفعيل `MISHKAT_USE_YTDLP=true` لاستخدام `yt-dlp` كبديل.

## ٣-ب) إدخال النصوص يدويًا (لفيديوهات بلا ترجمة)

كثير من الفيديوهات **لا تتضمن ترجمة على يوتيوب**، فيبقى نصها غائبًا عن القاعدة. لذلك يمكنك إدخاله يدويًا
من ثلاث جهات — ويُفهرس مباشرةً ويصبح المحرك يستشهد به مع التوقيت والرابط:

**أ) من الواجهة**: افتح «مكتبة النصوص» ← اختر الفيديو ← **＋ أضف نصًا** ← الصق النص أو اختر ملف ترجمة ← «💾 احفظ وفهرس النص».

**ب) من سطر الأوامر**:
```bash
# ملف ترجمة
node mishkat/cli.js import --video <VIDEO_ID> --file lesson.srt --title "عنوان الدرس"

# نص ملصوق أو ملف نصي عادي
node mishkat/cli.js import --video <VIDEO_ID> --text "الفقرة الأولى…"

# مجلد كامل: سمِّ كل ملف بمعرّف الفيديو (مثل: dQw4w9WgXcQ.srt)
node mishkat/cli.js import --dir ./subtitles
```

**ج) من الـ API**: `POST /api/import` بالجسم `{ videoId, content, filename, format, replace, title }` (يتطلب `MISHKAT_ADMIN_TOKEN`).

### الصيغ المدعومة
| الصيغة | مثال |
| --- | --- |
| SRT | `00:00:01,000 --> 00:00:04,500` (يدعم BOM و CRLF وأنماط ASS/SSA) |
| WebVTT | `00:00:01.000 --> 00:00:04.000 align:start` (+ التعليقات `NOTE`) |
| JSON | مخرجات `json3` من YouTube/yt-dlp |
| نص موقّت | `[02:15] نص…` أو `(02:15) نص…` أو `02:15 - نص…` |
| نص عادي | بلا توقيتات: تُوزَّع المقاطع على مدة الفيديو تلقائيًا (بتنبيه واضح أن التوقيت تقديري) |

* المقاطع التي لا تحتوي نصًا (مثل `[موسيقى]` أو `♪♪`) تُستبعد تلقائيًا.
* إن كانت الصيغة المُعلنة غير مطابقة، يتعرّف النظام على الصيغة الصحيحة ويُنبّهك.
* وتقرير **الفيديوهات التي تحتاج نصًا** يظهر في لوحة الإدارة (⚙) وفي الأمر `npm run missing`.

## ٤) محرك الذكاء الاصطناعي (منفصل وقابل للتبديل)

ضع **مفتاحًا واحدًا** في `.env` ويعمل المحرك تلقائيًا:

```bash
MISHKAT_AI_MODE=auto          # auto | gemini | groq | openai | openrouter | custom | off

GEMINI_API_KEY=...            # GEMINI_MODEL=gemini-2.0-flash
GROQ_API_KEY=...              # GROQ_MODEL=openai/gpt-oss-120b
OPENAI_API_KEY=...            # OPENAI_MODEL=gpt-4o-mini
OPENROUTER_API_KEY=...        # OPENROUTER_MODEL=google/gemini-2.0-flash-001
MISHKAT_LLM_BASE_URL=...      # أي مزوّد متوافق مع OpenAI
```

* **بدون أي مفتاح**: تعمل الأداة بـ«المحرك الاستخراجي» — تعرض أقرب النصوص مع التوقيت والروابط، وتوسّم مسائل التوسّع بوضوح.
* **مع مفتاح**: يجيب المحرك الذكي وفق منهجية علمية صارمة: خلاصة ← تحرير المسألة ← الأدلة من النصوص المرفقة ← أقوال أهل العلم ← مسائل متصلة وتوسّع ← تنبيهات.
* الإجابة تُبَثّ **مباشرة (Streaming/SSE)** حرفًا بحرف، وإن تعذّر البث تعود الواجهة تلقائيًا للوضع غير المتدفق.

### أوضاع اتساع الإجابة

| الوضع | السلوك |
| --- | --- |
| `strict` (صارم) | لا يجيب إلا بنصوص القناة، ويصرّح عند عدم وجود نص. |
| `balanced` (متوازن — الافتراضي) | النصوص أساسًا + مسائل متصلة موسومة أنها للاستزادة. |
| `open` (واسع المجال) | استفاضة موسوعية: المذاهب، القواعد، المقاصد، الفروق، النوازل المعاصرة، وتطبيقات عملية — مع تمييز صريح لما ليس من نصوص القناة. |

## ٥) واجهات الاستخدام

### أ) الواجهة الرسومية
* **شريط جانبي**: اختيار وضع الإجابة، بدايات سريعة، مكتبة الفيديوهات مع البحث، حالة القاعدة.
* **المحادثة**: إجابة متدفقة، بطاقات مصادر مرقّمة (التوقيت + الرابط + نسبة الصلة)، نسخ الإجابة، إعادة الصياغة، محادثة جديدة.
* **نافذة الفيديو**: التفريغ الكامل بالتوقيتات، بحث داخل النص، وزر **✨ تلخيص الدرس**.
* **لوحة الإدارة (⚙)**: سحب القناة أو إضافة فيديو واحد، مع سجل تقدّم مباشر، وحذف البيانات التجريبية.

### ب) سطر الأوامر
```bash
node mishkat/cli.js ask "ما حكم صلاة الجماعة؟" --mode open
node mishkat/cli.js search "زكاة الفطر" --topK 8
node mishkat/cli.js video <videoId> --q "النية"
node mishkat/cli.js add-doc --title "قاعدة فقهية" --text "..." --ref "..."
```

### ج) HTTP API
| المسار | الوصف |
| --- | --- |
| `GET /api/health` | حالة الخدمة والقاعدة |
| `GET /api/config` | إعدادات الواجهة + محرك الذكاء + القناة + الإحصاءات |
| `GET /api/stats` | إحصاءات القاعدة وسجل الأحداث |
| `POST /api/ask` | `{ message, mode, history, stream }` — إجابة (SSE أو JSON) |
| `POST /api/search` | `{ query, topK }` — نصوص فقط مع التوقيت والروابط |
| `GET /api/videos?q=&limit=` | قائمة الفيديوهات المفهرسة |
| `GET /api/video?id=<ID>&q=` | التفريغ الكامل أو البحث داخله (وتعمل أيضًا صيغة `/api/video/<ID>`) |
| `POST /api/summarize` | `{ videoId }` — تلخيص الدرس |
| `POST /api/ingest` | سحب القناة/فيديو (يتطلب `MISHKAT_ADMIN_TOKEN`) مع بثّ التقدّم |
| `POST /api/import` | إدخال نص/ترجمة لفيديو (يتطلب المدير) — SRT/VTT/JSON/نص |
| `GET /api/missing` | الفيديوهات التي لا يوجد لها نص مفهرس |
| `POST /api/purge-demo` | حذف البيانات التجريبية (يتطلب المدير) |

## ٦) نشر الواجهة على Vercel (اختياري)

بيئة Vercel **للقراءة فقط**، لذلك:

1. اسحب النصوص محليًا: `npm run ingest`
2. صدّر النسخة المفهرسة: `npm run export` → `mishkat/data/index.json`
3. ارفع المستودع إلى GitHub واربطه بـ Vercel، واضبط متغيّرات البيئة (مفتاح المزوّد + `YOUTUBE_CHANNEL_ID`).
4. `vercel.json` يقدّم الواجهة من `mishkat/public` ويضمّن ملف الفهرس مع الدالة:

```
api/index.js   ← دالة Serverless واحدة تخدم كل المسارات: /api/ask، /api/video، /api/import …
```

**لماذا دالة واحدة؟** خطة Vercel المجانية (Hobby) تسمح بـ **12 دالة Serverless لكل نشر**،
وكان المشروع يحتوي 21 ملفًا في `api/` فكان النشر **يفشل كاملًا** وتبقى النسخة القديمة معروضة.
الآن يعيد `vercel.json` كتابة كل مسارات `/api/*` إلى الدالة الواحدة:

```json
{ "source": "/api/(.*)", "destination": "/api/index?path=$1" }
```

والمنطق كله في `mishkat/lib/vehand.js` — واختبار آلي يمنع تجاوز حد الدوال مرة أخرى.

> ملاحظة: النسخة المنشورة **للقراءة فقط**: لا تدعم السحب (Ingest) ولا تعديل قاعدة البيانات؛
> حدّث البيانات بالسحب محليًا ثم أعد نشر `index.json`.

## ٧) التحقق من الجودة (١١٢ اختبارًا ناجحًا)

```bash
npm test        # 112/112 ✅
```

* **اختبارات الوحدات**: تطبيع العربية، المرادفات، التصنيف، تحليل الترجمات (json3/srv3)،
  تنظيف التكرار، تقسيم المقاطع، الروابط والتوقيتات.
* **اختبار قراءة ملفات الترجمة** (`mishkat/test/subtitles.test.js`): SRT/VTT/JSON/نص موقّت/نص عادي،
  BOM و CRLF وأنماط ASS وإعدادات موضع WebVTT، واستبعاد المقاطع الصوتية، والتراجع التدريجي بين الصيغ.
* **اختبار إدخال النصوص** (`mishkat/test/import.test.js`): الاستيراد من ملف ونص ملصوق ومجلد،
  واستخراج معرّف الفيديو من الروابط وأسماء الملفات، والاستبدال بلا تكرار، وتقرير النصوص الناقصة.
* **اختبارات الخادم**: كل مسارات API، البثّ SSE، حماية المسارات، صلاحيات المدير، المتجر البديل.
* **اختبار مسارات Vercel** (`mishkat/test/vercel.test.js`): يستدعي الدالة `api/index.js` نفسها
  عبر خادم يحاكي بيئة Serverless **وإعادة الكتابة** (`/api/x?y=1` ⟶ `/api/index?path=x&y=1`)،
  ويتأكد من أن كل مسار في الواجهة يستجيب فعلًا، وأن النسخة المنشورة (القراءة فقط) تعمل،
  **ويمنع أي ملف من استخدام ESM داخل مشروع CommonJS** (السبب الفعلي لخطأ 500 في النسخة القديمة)،
  **ويمنع تجاوز حد الخطة المجانية (12 دالة)**، ويتحقق من طبقة توافق المسارات القديمة ومن عمل `/api/diagnose`.
* **اختبار تكاملي شامل** (`mishkat/test/e2e.test.js`): يُشغّل خادمًا محليًا **يحاكي يوتيوب**
  (صفحة القناة + متابعة التحميل + واجهة المشغّل + ملف الترجمة) وخادمًا **يحاكي مزوّد الذكاء الاصطناعي**،
  ثم يُنفّذ المسار كاملًا:
  `سرد القناة ← استخراج النصوص ← التنظيف والتقسيم ← الفهرسة ← الاسترجاع ← الإجابة المتدفقة`
  ويتأكد من: مطابقة التوقيت في الرابط، ووصول المصادر المرقّمة والروابط إلى المحرك الذكي،
  وصحة التلخيص، وصلاحية ملف `index.json` للنشر، والعمل عبر HTTP API.

> هذا الاختبار يثبت أن الأداة تعمل فعليًا بلا إنترنت ولا مفاتيح — قبل سحب بيانات قناتك.

## ٨) كيف تعمل الأداة (خط الأنابيب)

```
قناة يوتيوب                                   نصوص مُدخلة يدويًا
```

## ١٠-ب) حل مشكلة «حدث خطأ: HTTP 500» على الموقع المنشور

للخطأ سببان تراكما معًا — الأول يعطّل الواجهة، والثاني يمنع وصول الإصلاح إلى الموقع:

### السبب ١: النسخة القديمة تنهار عند الطلب
الموقع المنشور كان يعمل على فرع `main`، وهو ما زال النسخة القديمة (T.M.D AI v1) التي كانت:
* تستخدم صيغة **ESM** (`export default`) داخل مشروع **CommonJS** (بلا `"type": "module"`) ⟹ تنهار دالة
  `/api/chat` عند التحميل فتُعيد المنصة خطأ 500 **بلا جسم JSON**، ولهذا تظهر الرسالة «HTTP 500» بلا تفسير.
* وتحتاج `GEMINI_API_KEY` وإلا أرجعت 500 صريحًا.

### السبب ٢: النشر يفشل فيبقى الموقع على نسخة قديمة (الأهم)
خطة Vercel المجانية (Hobby) تسمح بـ **12 دالة Serverless لكل نشر**. كان مجلد `api/` يحتوي **21 ملفًا**،
فيفشل النشر كاملًا برسالة:

```
Error: No more than 12 Serverless Functions can be added to a Deployment on the Hobby plan
```

وعلامته أن حالة النشر على GitHub تظهر **failure** (أو Error في لوحة Vercel) **بينما الموقع يظل يعمل**
على آخر نشر ناجح — فيبدو كأن تعديلاتك لم تُرفع، والحقيقة أن النشر مرفوض.

**كيف عالجناه:** كل المسارات الآن في **دالة واحدة** `api/index.js` (العدد = 1)، و`vercel.json` يعيد
كتابة كل `/api/*` إليها عبر `?path=`، واختبار آلي يفشل إذا تجاوز عدد ملفات `api/` الحد المسموح.

**الحل (خطوة واحدة):** انشر النسخة الجديدة «مشكاة»:
1. افتح طلب الدمج (Pull Request) واختر **Merge** ⟹ يُنشر تلقائيًا على Vercel.
   *(أو من إعدادات Vercel: Settings ← Git ← Production Branch ← اختر فرع العمل)*
2. بعد النشر افتح الموقع واعمل **إعادة تحميل قوية** (Ctrl + F5) لأن المتصفح قد يحتفظ بالواجهة القديمة.
3. اختياريًا أضف مفتاح ذكاء اصطناعي (`GEMINI_API_KEY` أو `GROQ_API_KEY`) لتوسيع الإجابات؛
   وبدونه تعمل الأداة بالمحرك الاستخراجي (نصوص + توقيت + روابط) بلا أي خطأ.

### أدوات التشخيص المدمجة

| الأداة | الاستخدام |
| --- | --- |
| `GET /api/diagnose` | فحص شامل للنسخة المنشورة: ملف الفهرس، القاعدة، محرك الذكاء، متغيرات البيئة، واختبار استرجاع حقيقي |
| زر **🩺 فحص تشغيل الأداة** في لوحة الإدارة (⚙) | نفس الفحص من الواجهة بشكل مقروء |
| `npm run doctor` | نفس الفحص محليًا من سطر الأوامر |

### ما أُضيف لمنع تكرار المشكلة
* **طبقة توافق** للمسارات القديمة (`/api/chat`, `/api/settings`, `/api/image`, `/api/upload`, `/api/owner-login`…):
  تُعيد رسالة عربية واضحة تطلب إعادة تحميل الصفحة، بدل انهيار 500 لمن لديه واجهة قديمة مخزَّنة.
* **اختبار آلي** (`mishkat/test/vercel.test.js`) يمنع أي ملف في `api/` من استخدام صيغة ESM،
  ويتأكد أن كل ملف يُحمَّل فعليًا، ويرفض وجود `"type": "module"` بلا تحويل كامل.
* **رسائل خطأ قابلة للتنفيذ** في الواجهة: بدل «HTTP 500» تشرح السبب المحتمل وزرّ الفحص مباشرة.
* **اختبار حد الدوال** (`mishkat/test/vercel.test.js`): يفشل فورًا إذا تجاوز عدد ملفات `api/`
  اثني عشر ملفًا (حد الخطة المجانية)، أو إذا أُضيف إعداد `api/*.js` الذي كان يضاعف الدوال.
* **`.vercelignore`**: يمنع نشر النسخة القديمة في `legacy/` والاختبارات وقواعد البيانات المحلية.

## ١١) ملاحظات شرعية وقانونية

* الأداة **وسيلة عرض وتوثيق للنصوص**، وليست جهة إفتاء رسمية، ولا تصدر فتاوى في النوازل الشخصية.
* كل إجابة تُحال إلى نص القناة وتوقيته ورابطه؛ وما ليس من نصوص القناة يُوسَم صراحةً أنه للاستزادة.
* عند المسائل الشخصية أو الخصومات أو المسائل المستجدة، يُرجَع إلى مفتٍ متخصص.
* المحتوى العلمي ملكٌ لأصحاب القناة، والأداة تستشهد بالمصدر وتُعيد الرابط الأصلي، ويُرجى مراعاة شروط استخدام القناة.
* النسخة القديمة من المشروع (كانت ببيانات وهمية) نُقلت إلى `legacy/tmd-v1/` للرجوع فقط، ولم يعد يعتمد عليها أي شيء في المسار الحالي — يمكن حذف المجلد بأمان: `rm -rf legacy/tmd-v1`.
